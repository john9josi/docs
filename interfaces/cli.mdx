The Ulysses CLI works against the same workspace as the [web app](https://app.tryulysses.com). Use it for scripts, automation, and AI agents.

## Install

```bash
curl -fsSL https://install.tryulysses.com/cli | sh
ulysses-cli --version
```

The installer adds [uv](https://docs.astral.sh/uv/) if it's missing, downloads the signed release from `install.tryulysses.com`, verifies its SHA-256 checksum and signature, and puts `ulysses-cli` on your `PATH`.

Update with `ulysses-cli update`.

## Sign in

If you were invited to an organization, you already have an account:

```bash
ulysses-cli auth login
ulysses-cli auth whoami
```

Device login opens in your browser. Never pass a password to the CLI.

- Choose an environment with `--env production` (default), `staging`, or `local`.
- Use named profiles with `--profile <name>`.
- Switch workspaces with `auth contexts`, then `auth use <tenant-id>`.

Tokens are stored in your OS keychain when available. Profile settings live in `~/.ulysses/config`. Sign out with `auth logout`, or revoke a device in the web app under **Settings → Devices**.

### Sign up without an invitation

New accounts start with a personal workspace. Signup emails you a setup link:

```bash
ulysses-cli auth signup --email you@example.com
```

Optional flags: `--first-name`, `--last-name`, and `--env`. Finish setup in your browser, then run `auth login`. You can't sign in until setup is complete.

<Note>
  A success response means the request was accepted. It doesn't confirm that a workspace was created, and it doesn't reveal whether the email is already registered.
</Note>

## Run a command

```bash
ulysses-cli [--output json|human] <resource> <action>
```

`--output` must come before the resource. Output is human-readable in a terminal and JSON when piped. Run `ulysses-cli` on its own to see every command.

## Commands

### Authentication

| Command | What it does |
| --- | --- |
| `auth signup --email <address>` | Email a setup link. |
| `auth login [--env …] [--profile <name>]` | Sign in with device login. |
| `auth whoami` | Show who you're signed in as and the active profile. |
| `auth contexts` / `auth use <tenant-id>` | List workspaces / switch workspace. |
| `auth sessions` / `auth revoke <session-id>` | List / revoke device sessions. |
| `auth logout [--all]` | Sign out. |

### Team

These commands need an active workspace. Inviting, updating, and removing teammates require the workspace **admin** role.

| Command | What it does |
| --- | --- |
| `users list [--limit N]` / `users show <user-id>` | List / show teammates. |
| `users invite --email <address> [--role member\|admin]` | Email an invitation. |
| `users update <user-id> [--role …] [--status ACTIVE\|DEACTIVATED]` | Change a teammate's role or status. Pass at least one flag. |
| `users remove <user-id>` | Remove a teammate. |

### Portfolio

| Command | What it does |
| --- | --- |
| `organizations list` / `show` | Organizations in the workspace. |
| `projects list` / `show` / `create` / `update` | Projects. Creating and updating require `project:write`. |
| `matches show <project-id>` | Stored opportunity matches for a project. |
| `opportunities list` / `show` | Funding opportunities. |
| `awards list` / `show` | Awards. |
| `activity list` | Recent activity. |
| `links resolve <kind> <id>` | Web app URL for a `project`, `opportunity`, or `award`. |

Get IDs from a `list` command. Don't guess them.

## Scripts and AI agents

Use JSON output and treat the response envelope as the contract:

```bash
ulysses-cli --output json projects list --limit 50
```

- Successful responses include `ok: true` and `result`.
- Failures include `ok: false`, `error`, and often `next_actions`. Stop on failure.
- Prefer read commands unless a write was explicitly requested.
- Never print access or refresh tokens.
